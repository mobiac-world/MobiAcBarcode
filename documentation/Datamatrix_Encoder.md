



# Square Data Matrix for Business Central

Pure AL generator for **square Data Matrix ECC200** symbols using ASCII encodation (including Upper Shift, so the full Latin-1 range 0–255 is supported).

## Compatibility

- Business Central Online
- Business Central On-Premises
- No .NET interoperability
- No external web service
- No barcode font
- Apache License 2.0

The sample `app.json` targets Business Central 24 / runtime 13. Adjust `platform`, `application`, and `runtime` to your target version if needed.

## Supported scope

- Latin-1 values 0 through 255
- Compact encoding of two consecutive digits
- ECC200 Reed-Solomon error correction
- Square symbols only: 10x10 through 48x48 modules
- SVG output
- Optimized uncompressed monochrome 1-bit BMP output
- BMP presets with a maximum dimension of 128, 256, 512, or 1024 pixels
- Exact module sizing through `GenerateBitmapByModuleSize`

The generator never switches to a rectangular symbol. Values requiring more than 174 data codewords raise an error.

## Public API

The encoder lives in namespace `EchMot.MobiAc.Barcode`.

```al
using EchMot.MobiAc.Barcode;

var
    Generator: Codeunit "MobiAc DataMatrix Generator";
    TempBlob: Codeunit "Temp Blob";
begin
    Generator.GenerateSvg('GH-DOÜ567', 8, 4, TempBlob);
    Generator.GenerateBitmap('GH-DOÄ567', Enum::"MobiAc Bitmap Size"::Medium, 4, TempBlob);
    Generator.GenerateBitmapByModuleSize('GH-DOA567', 8, 4, TempBlob);
end;
```

## Usage in reports

Reports do not call this codeunit directly. They go through codeunit 50064 `"MobiAc Barcode Provider"`,
which wraps the generator and can be replaced through integration events.
See [BarcodeProviderExtensibility.md](BarcodeProviderExtensibility.md).

## Shared rendering layer

`"MobiAc DataMatrix Generator"` only builds the module matrix. Everything that turns modules into
pixels is a set of procedures on codeunit 50064 `"MobiAc Barcode Provider"`
([MobiAcBarcodeProvider.Codeunit.al](../src/codeunit/MobiAcBarcodeProvider.Codeunit.al)) and is
shared with codeunit 50065 `"MobiAc Code128 Generator"` (see [Code128_Encoder.md](Code128_Encoder.md)).
It used to be a separate codeunit 50060 `"MobiAc Barcode Renderer"`, merged into the provider to
save a codeunit; both encoders hold a `"MobiAc Barcode Provider"` variable for this purpose, and
the provider in turn calls the encoders to run the default `GenerateBarcodeToBlob` implementation
— a deliberate two-way reference, which AL allows between codeunits without issue. All three
objects live in namespace `EchMot.MobiAc.Barcode`:

| Procedure | Purpose |
| --- | --- |
| `RenderSvg` | Module matrix to SVG, adjacent black modules merged into one rectangle |
| `RenderBitmap` | Module matrix to uncompressed 1-bit BMP |
| `IsBlackModule`, `GetMatrixBit`, `SetMatrixBit` | Range-checked matrix access |
| `BitmapSizeToPixels` | Maximum edge length of a `"MobiAc Bitmap Size"` preset |
| `ValidateRenderArguments`, `PowerOfTwo`, `Max` | Shared helpers |

The matrix is a row-major `List of [Boolean]` with `Rows * Columns` entries, `true` = black. Module
width and module height are independent and the quiet zone is given in pixels, so the same renderer
serves the square Data Matrix and the one-row Code 128 symbol. A new symbology only has to build a
matrix; it inherits both output formats.

## Output geometry

Both SVG and BMP outputs are square because the selected ECC200 matrix is square and the quiet zone is identical on all four sides. Every module remains exactly square. The preset BMP renderer chooses the largest integer module size that fits the selected maximum dimension.

For printing, `GenerateBitmapByModuleSize` is preferable because it gives explicit control over pixels per module.

## Bitmap renderer optimization

The BMP renderer uses a 1-bit black/white palette and packs eight pixels into each output byte. Compared with the previous 24-bit renderer, pixel data is reduced from three bytes per pixel to one bit per pixel. This reduces stream writes and Blob size substantially while preserving lossless, sharp modules. BMP scanlines remain padded to the required four-byte boundary.

## RDLC

Use BMP as a database image with MIME type `image/bmp`. Expose the generated bytes from a Blob or Temp Blob in the report dataset. Keep the image control square and do not resize it non-proportionally.

## Implementation note: boolean evaluation in AL

AL evaluates every operand of an `AND` or `OR` expression. A range check cannot be used as a guard operand in front of a list or string access in the same expression, because the access is evaluated as well.

The ECC200 module placement traverses diagonally and deliberately steps outside the data region, and the ASCII encoder looks ahead one character to detect digit pairs. Both range checks therefore live inside `IsFreeModule` and `IsDigitAt` instead of being separate operands of the calling condition. Do not flatten these helpers back into the conditions; that reintroduces out-of-range list and string access at runtime.

## Production validation

Before production use:

1. Compile against the exact Business Central target symbols.
2. Compare every used symbol size against a trusted ECC200 reference encoder.
3. Decode test output with at least two independent scanners.
4. Test the actual printer, resolution, label material, module size, and quiet zone.
